# APK 50 / патч 49: обновление перед запуском Unity

Сохранить tesl-reborn-update-49-50.zip в E:\TESL-build. В WSL:

```bash
python3 -m zipfile -e /mnt/e/TESL-build/tesl-reborn-update-49-50.zip /mnt/e/TESL-build/update-49-50
bash /mnt/e/TESL-build/update-49-50/apply.sh
git -C ~/tesl-reborn-android-review push
```

Патч поверх 47. После Actions скачать новый Builder из ветки
android-ui-and-update-loader, включить Expert mode → APK only, собрать и установить
APK 50 поверх текущего. OBB и языки заново не нужны. Для новой стартовой проверки
необходима одна установка APK: на старом APK 46 обновление хука продолжает работать
по прежней схеме с применением при следующем запуске.

## Обычный холодный запуск

Перед Unity открывается небольшой чёрный экран проверки Reborn. Никакого выбора
ресурсов при готовой игре нет. Проверка получает манифест, скачивает новый хук,
проверяет совместимость, размер, SHA-256 и заголовок Android core. Затем записывает
его в приватный кеш загрузчика и атомарно публикует pending. Unity запускается
один раз: прежний загрузчик API 1 выбирает этот pending сразу в первом boot.
Его механизм подтверждения и отката сохранён; версия не помечается активной
до ready() нового хука. При ошибке инициализации откат происходит при следующем
старте — горячая замена частично установленных перехватов не выполняется.

Сеть ожидается не дольше 12 секунд. «Играть сейчас» и Android Back пропускают
проверку и запускают установленную версию. При сетевой ошибке игра также запускается.
При отключённых обновлениях/safe mode сетевых запросов нет. Если Unity уже работает
в фоне, её продолжают: состояние работающего загрузчика не переписывается. Проверка
наличия процесса повторяется перед публикацией pending, если игра успела запуститься
другим путём. Возврат в уже работающую игру не является новым холодным запуском.

Запросы идут только по HTTPS, без данных аккаунта, без перехода на другой origin
и без HTTP-redirect. Лимит манифеста 32 КиБ, хука 4 МиБ. Повреждённый файл,
понижение ревизии и ранее отвергнутый хук не устанавливаются. Предыдущее booting
сначала передаётся прежнему механизму восстановления. Отмена запрещает последующую
публикацию результата фонового запроса. Совместимая старая версия остаётся доступна.

Сам встроенный патч в APK 50 — 49. Для проверки применения нового OTA в этом же
запуске понадобится следующая опубликованная ревизия выше 49. После свежей нативной
проверки хук не выполняет сразу второй такой же запрос в этом процессе. Смена
языка через Game Data сохраняет свой короткий переход и не добавляет сетевую паузу.
Обновления нативной Android-части по-прежнему требуют APK.

## Подпись версии всю загрузку

Раньше подпись скрывалась при исчезновении первого LoadingScreen, примерно на 30%.
Теперь она остаётся до завершения MainMenuNavManager.Init; исчезновение первого
компонента загрузки больше не считается готовностью игры. Если этот API недоступен,
используется наблюдаемое состояние менеджера главного меню. В обычном меню/бою
подпись скрыта. Положение из 47 сохранено. Фактическое поведение следует проверить
на Pixel; здесь проверяются переходы состояния и код, а не кадры реального клиента.

## Cancel: проверка гипотезы о разрешении

Моргание не объявляется исправленным. В 49 добавлена отдельная диагностика:
- ширина и высота рендера Unity;
- прямые вызовы доступных managed Screen.SetResolution и их аргументы;
- размер Settings, локальный/мировой масштаб и масштабы четырёх родителей;
- scaleFactor родительского Canvas.

Запись по кадрам включается на две секунды после касаний внутри открытого Settings,
независимо от того, реализован Cancel через Unity Button или другой контрол.
Одинаковые состояния не дублируются, хранятся последние 60 изменений, запись на диск
объединяется до 10 раз в секунду. Снимки попадают в
**tesl-reborn-display-status.json**, результат стартового обновления — в
**tesl-reborn-prelaunch-status.json**. APK 50 включает оба в обычный отчёт.

Если разрешение остаётся тем же, а масштаб Popup/Canvas меняется, это укажет на
анимацию или перестройку интерфейса. Если меняются width/height либо виден
SetResolution — на смену рендера. Диагностика ничего не блокирует в графических
настройках и не подменяет действие Cancel действием OK.

После установки открыть Settings → нажать Cancel → подождать две секунды → снова
Settings → Game Data → отправить отчёт. Так можно отличить эти две причины без ADB.

## Проверки

Выполнен сквозной тест Java-stager → неизменённый JS loader API 1: новый pending
выбирается, исполняется и подтверждается в первом boot, без второго запуска.
На JVM проверены хеш, формат, происхождение URL, типы/границы чисел, отмена,
safe mode/disabled, работающая Unity, предыдущая неудачная инициализация,
понижение ревизии и повтор отвергнутого обновления. Выполняются в GitHub Actions.
Прогнаны JS/30 Python-тестов, Java→DEX, native JVM и сборка/подпись/выравнивание
синтетических APK трёх форматов. Launcher теперь использует чёрную тему вместо
NoDisplay: ожидать асинхронный запрос в NoDisplay нельзя. Manifest и наличие
PrelaunchUpdater в DEX проверяются после сборки APK.

Реального Pixel и Windows EXE в среде нет. Кнопку пропуска, сетевой таймаут,
положение подписи и длительность её отображения нужно подтвердить на телефоне.
Публичные ветки/main/настройки репозитория этим архивом не переименовываются.
