# TESL Reborn Builder — тестовая версия

## Возможности

- Поиск Steam-библиотек Windows, включая дополнительные диски; ручной выбор игры
  или StreamingAssets. Исходная игра и исходный XAPK используются только для чтения.
- Входной Android-пакет: оригинальный single-base XAPK, package
  `com.bethsoft.theelderscrollslegends`, versionCode 11009, с arm64 APK и OBB.
- Выбор языков, включая es_mx; язык по умолчанию — система телефона либо явный.
- Независимый выбор результата XAPK или APK+OBB и встроенных/отдельных пакетов.
- Android-экран подготовки до запуска Unity: установка встроенных пакетов,
  скачивание common+языка, докачка, проверка SHA-256, удаление языка, запуск игры.
- Временный сервер отдаёт только catalog.json и перечисленные пакеты. Доступ
  защищён случайным кодом. Папка исходной игры сервером не публикуется.
- Автоостановка: 60 секунд после подтверждения установленного набора с телефона
  или 15 минут бездействия. Активная передача не прерывается таймером.

## Получить Windows EXE

Сборку выполняет GitHub Actions `Build Windows Builder` на Windows. После push
ветки с этим workflow открой вкладку Actions своего форка, дождись успешного
завершения и скачай artifact `TESL-Reborn-Builder-Windows`. Распакуй архив в
отдельную папку, например `E:\TESL-build\Builder`, и запусти
`TESL-Reborn-Builder.exe`. Python, Java, Node, WSL и Git для работы EXE не нужны.
Java, apktool, signer, zipalign, Frida gadget и Android setup DEX входят в сборку.

Для самостоятельной сборки EXE из исходников на Windows нужны Python 3.12,
Node 18+ и JDK 17. Выполни из корня репозитория:

```powershell
python -m pip install -r builder/requirements.txt
python -m builder.bootstrap_tools
python tools/prepare_emojis.py
python android-setup/build.py
npm ci
npm run build
npm test
```

Затем создай `vendor/jre` через jlink по рецепту workflow и выполни
`python -m builder.package_windows`. Не запускай PyInstaller для Windows в Linux:
его результат зависит от ОС сборки.

## Создать установочный комплект

1. Выбери обнаруженную ПК-игру или укажи её папку.
2. Укажи оригинальный XAPK. Файлы, недостающие в OBB, восстанавливаются из ПК-игры
   по инвентарю versions.json. Произвольные будущие обновления ПК, не описанные
   этим инвентарём, автоматически не переносятся.
3. Выбери языки и поведение по умолчанию. «По системе» означает Android, не Windows.
   Если пакет системного языка не подготовлен, телефон предложит другой язык
   или скачивание; английский служит fallback для неподдерживаемой локали.
4. Выбери XAPK или APK+OBB. Отметь встраивание пакетов либо оставь их для передачи.
5. Нажми «Собрать». Результаты находятся в `output/build-…` в выбранной рабочей
   папке; по умолчанию она рядом с EXE. Рабочие файлы `work/run-…` удаляются после
   завершения. Существующие результаты не перезаписываются.

Сборщик откажется писать внутрь исходной папки игры, включая случай, когда EXE
положен туда. Выбери отдельную рабочую папку. Проверяется свободное место;
для всех языков нужны несколько больших промежуточных копий.

Подпись пока совместима с прежним embedded debug certificate uber-apk-signer
1.3.0 (SHA-256 `1e08a903aef9c3a721510b64ec764d01d3d094eb954161b62544ea8f187b5953`).
Это тестовая подпись, не отдельный приватный ключ релиза. Не удаляй рабочую игру
при ошибке обновления: сначала проверь подпись и свободное место.

При APK+OBB скопируй содержимое созданной папки `Android/obb` на телефон в
соответствующий каталог. При XAPK это делает поддерживающий такой формат
установщик. Экран подготовки проверяет наличие OBB до запуска игры.

Ресурсы эмодзи не распространяются внутри EXE: сборщик читает совпадающие
проверенные файлы из установленного ПК Reborn либо скачивает pinned официальный
архив 1.3.1-beta и извлекает только два файла. Для этого шага может требоваться
интернет. DLL не выполняется и в Android-пакет не включается.

## Передать ресурсы по локальной сети

После сборки нажми «Начать передачу». Для уже готовых пакетов можно отдельно
выбрать `output/build-…/resources/catalog.json`, не пересобирая игру.

ПК и телефон должны иметь сетевую доступность друг к другу. При запросе Windows
Firewall разреши серверу доступ в частной сети. Проверь выбранный IP, особенно
если на ПК есть VPN/виртуальные адаптеры. Сборщик не меняет правила firewall.
Локальный HTTP не шифрует трафик: используйте доверенную сеть либо HTTPS.

На телефоне в новом экране подготовки введи показанный адрес и временный код.
Выбери язык и нажми скачивание. Сначала установится обязательный `common`, затем
язык. После установки телефон подтверждает завершение серверу. Можно выключить
ПК: установленные пакеты остаются на телефоне.

QR содержит `teslreborn://resources?url=…&token=…`. Его можно открыть внешним
сканером, поддерживающим такие ссылки; встроенного сканера камеры в приложении
пока нет. Ручной ввод адреса и кода поддерживается независимо от QR.

После первого успешного запуска приложения подготовка автоматически пропускается,
если OBB и выбранные пакеты доступны. Вернуться можно кнопкой `Resources` в чате
либо deeplink. Изменение языка уже запущенной Unity требует полного перезапуска.

## Передача через интернет

Android принимает публичные HTTPS-источники с тем же форматом catalog.json/packs.
Для HTTP разрешены только числовые локальные IPv4-адреса. Переадресации, URL с
паролями и параметры query не поддерживаются транспортом ресурсов.

В «HTTPS / интернет…» можно указать внешний HTTPS URL и порт. Если TLS завершает
сам сборщик, укажи PEM-сертификат и ключ; сертификат должен быть доверенным
телефоном и соответствовать домену. Если TLS завершает отдельный reverse proxy,
поля сертификата и ключа в сборщике оставь пустыми. Proxy должен сохранять
Authorization и Range и передавать POST /complete для автоостановки.
В этой версии принимается PEM-ключ без пароля; запроса пароля в скрытой консоли
нет. Не включайте приватный ключ в каталог раздачи.

Публичная доступность, DNS, сертификат и маршрутизация настраиваются отдельно.
Проброс портов, туннели, обход CGNAT и выпуск сертификата сборщик не делает.
Обычная локальная передача этого не требует.

## Что проверено и что ещё нужно проверить

Локально проверяются разделение языков и общих ресурсов, защита исходной папки,
пакеты и хеши, HTTP-авторизация/allow-list/Range/ACK/таймеры. Реальный Java-код
PackInstaller выполняется на JVM с синтетическими пакетами: докачка, проверка,
установка, удаление и отклонение опасных путей. Android Activity компилируется в DEX.

Синтетическая интеграция проходит путь от исходного XAPK через manifest, smali,
добавление DEX, ELF-патч, упаковку, выравнивание и проверку подписи до обоих
форматов результата. Исходные файлы остаются неизменными.

Это ещё не проверка настоящей игры на телефоне. Требуются Windows-сборка EXE,
запуск GUI, конвертация настоящего StreamingAssets, чистая установка на тестовом
профиле, локальная передача/обрыв/повтор и проверка выбранного языка. Код
override языка обрабатывает строковую/распознанную enum-сигнатуру; неизвестная
сигнатура оставляет системную локаль и пишет диагностическое сообщение.
Кнопка Resources и новая точка входа также требуют проверки на устройстве.

Пакеты импортируются с receipt-last commit. До полного завершения установка
не считается готовой; файлы пакета сначала проверяются в staging. Это не общая
транзакция для всех файлов ОС: после аварии нужно повторить установку.
Стартовая проверка receipts проверяет наличие и размеры данных; служебный
__info должен существовать и быть непустым, но Unity может менять его размер.
Временные загрузки находятся в приватном Android cache и могут быть очищены ОС.
Удаляются только файлы управляемых пакетов,
не используемые другими receipts; старый неучтённый кеш не очищается целиком.

Автообновление самого APK и универсальная конвертация PC DLL здесь не реализованы.
По умолчанию сохраняется текущий тестовый GitHub-канал патчей; перед публичным
релизом нужен отдельный стабильный канал и решение по ключу подписи.
