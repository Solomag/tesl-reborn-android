# Лаунчер: обновление при уже запущенной игре

Изменение лаунчера (Java, `android-setup`), не OTA: действует после пересборки
APK в Builder.

## Что было

`LaunchActivity` проверяет обновление перед холодным стартом Unity и сразу
готовит его (`PrelaunchUpdater.check` → `pending`); загрузчик применяет его в
этом же запуске. По отчётам 20–23 так и происходило: ревизии 73–76 появлялись в
первой сессии после публикации.

Если процесс игры остался в памяти, нажатие на иконку только возвращало игру:
проверка пропускалась, а внутриигровая проверка идёт один раз при старте.
Обновление ждало, пока игру не выгрузят вручную.

## Что теперь

- Если игра запущена, лаунчер читает только манифест (`PrelaunchUpdater.offer`):
  без скачивания и без записи состояния — пока Unity работает, менять
  `state.json` нельзя.
- Есть новая ревизия → экран «Reborn update N is available. Restart the game to
  apply it. An unfinished match will be lost.» с кнопками **Restart now** и
  **Back to the game**.
- **Restart now**: процесс игры завершается (`GameProcess.stop`, тот же код, что
  уже использовал `ResourceActivity`), затем обычная предзапусковая проверка
  скачивает и готовит ревизию, и игра запускается уже с ней.
- Для запущенной игры проверка выполняется не чаще раза в 10 минут
  (`tesl-reborn-prelaunch-status.json`), ожидание ответа — до 8 с, отказ тоже
  откладывает вопрос на 10 минут.
- Отклонённые и уже подготовленные ревизии, режим восстановления после
  неудачного запуска и выключенный/safe-mode апдейтер не предлагаются.

## Проверки

- `android-setup/test_prelaunch.py`: `offer()` сообщает о новой ревизии, ничего
  не скачивая и не записывая; не предлагает уже подготовленную, отклонённую и
  во время восстановления. Подготовленное ядро загружается в первом запуске
  Unity (тот же тест через `tests/prelaunch-loader.cjs`).
- Все исходники `android-setup/src` компилируются против `android.jar` API 35.
- Сам экран и перезапуск процесса проверяются только на устройстве.
