# Сверка Android-порта с предоставленной DLL Reborn

Проверены метаданные и выбранные тела методов `TeslRebornPlugin.dll`, версия
сборки 1.3.1, строка версии 1.3.1-beta, SHA-256
`ffb96e44883ddcfb4a8c077a11703ffed50d8c5a4a094839fe314569a09a108b`.
Сопоставление — с `hook.ts` OTA 58 на основе 57 (`4054c4d`). Это сверка именно
присланного бинарника, а не обещание совпадения с будущими версиями ПК-плагина.
Оригинальные DLL и материалы игры в репозиторий не добавлены.

В пространстве имён патчей найдены 38 именованных классов верхнего уровня.
В их числе модели данных, помощники, пустые и диагностические патчи — это
не 38 независимых пользовательских функций. Сгенерированные компилятором
корутины и замыкания отдельно в таблице не считаются.

«Есть аналог» означает наличие соответствующей реализации в Android, иногда
с управлением для сенсорного экрана. Это не утверждение побайтового совпадения,
полной эквивалентности всех веток или новой проверки каждого пункта на телефоне.

## Реальные оставшиеся различия

1. **Дата и время матча.** ПК `MatchEntryPatch.CreatePlayedAtText` создаёт
   отдельную подпись, `FormatPlayedAt` использует культуру игры (для pl-PL
   специальный формат `dd-MM-yyyy HH:mm`, для остальных `g`). Android получает
   и сохраняет `playedAt`, но пока не рисует его в истории.
2. **Немедленная синхронизация истории после изменения колод.** ПК
   `InventoryPatch.UpdateMatchEntryData`, `RemoveDeckStats`, `AddDeckStats` и
   `StatsPatch.RemoveDeckFromMatchEntryData` обновляют локальные данные после
   операций. Android вызывает `refreshDeckStats(true)` через секунду после
   возврата CreateDeck/SaveDeck/DeleteDeck; возврат метода не гарантирует
   завершение сетевого запроса. При этом `matchEntryData` не обновляется.
   Подсказка истории может сохранять старое имя/статус удаления до новой загрузки
   расширенных данных. Требуется привязка к успешному результату запроса.
3. **Отдельный размер шрифта чата.** ПК `FriendsChatWinPatch.FontSize` хранит
   настройку в PlayerPrefs и изменяет шрифт сообщений/превью через Ctrl+колесо
   или Ctrl+плюс/минус. В Android сохранённый pinch-масштаб меняет всё окно,
   а независимой настройки размера текста пока нет. Это различие функций,
   хотя управление размером окна на телефоне уже есть.
4. **Круглая рамка атрибутов в истории.** ПК `MatchEntryPatch.UpdateDeckImages`
   добавляет `static-circle-btn`, увеличивает рамку и немного уменьшает значки.
   Android использует исходные значки с прозрачными областями для нажатия и
   нативной подсказкой; отдельная круглая рамка из этого метода не перенесена.
   Это косметическое отличие, информация о колоде по тапу уже отображается.

Также не выполнено полное сравнение внешних словарей переводов по всем ключам:
`TranslationLoader` ПК читает `translations/<language>.json` из каталога данных.
Наличие реализации подмены строк в Android не доказывает равенство содержимого
всех этих файлов. Версия ПК-плагина в подписи порта задаётся портом, а не
извлекается автоматически из обновляемой DLL.

Приоритет следующего переноса: успешные callback операций с колодами → дата
матча → необязательный отдельный размер текста → декоративные рамки.
В OTA 58 эти новые функции не добавляются: выпуск исправляет первый запуск UI.

## Границы проверки

Методы с перечисленными различиями проверены по IL предоставленной DLL и
сопоставлены с текущим TypeScript. Полная функциональная эквивалентность сетевых
гонок, серверных ответов, всех экранов и всех локализаций не доказана.
DLL не становится исполняемым Android-плагином автоматически: её поведение
переносится в IL2CPP-перехватчики, а обновления этих перехватчиков распространяются
через существующий GitHub OTA-канал.
