# Проверка новой сборки

## Применить патч и получить EXE

Сохрани `tesl-reborn-builder.patch` в `E:\TESL-build`.
В Ubuntu WSL выполни:

```bash
cd ~/tesl-reborn-android-review
git status --short
git am /mnt/e/TESL-build/tesl-reborn-builder.patch
```

Патч подготовлен поверх `59bead9` в ветке `android-ui-and-update-loader`.
Если git сообщает конфликт, не запускай повторный git am: сохрани вывод ошибки.
Чтобы отменить незавершённое применение: `git am --abort`.

Для отправки нового workflow GitHub может потребовать дополнительный scope.
Выполни отдельно и закончи авторизацию в браузере:

```bash
gh auth refresh -h github.com -s workflow
```

Затем:

```bash
git push
```

Открой https://github.com/Solomag/tesl-reborn-android/actions и найди
`Build Windows Builder` для своего коммита. Если Actions отключён в форке,
включи его до push. После успешного запуска скачай artifact
`TESL-Reborn-Builder-Windows`, распакуй и запусти EXE. Если job упал,
нужен лог первого упавшего шага. Исходный ZIP — запасная копия исходников,
его не нужно накладывать поверх репозитория вместе с патчем.

## Проверить сначала один язык

1. Запускай EXE из отдельной папки, например `E:\TESL-build\Builder`.
2. Укажи ПК-игру и оригинальный XAPK. Выбери английский и русский.
3. Сначала выбери APK+OBB и встроенные пакеты, язык по умолчанию русский.
4. Установи APK поверх текущей игры. При необходимости используй
   `adb install --no-streaming -r "полный-путь-к-APK"` в PowerShell.
   Не удаляй текущую игру и её данные. OBB из результата скопируй в
   `/sdcard/Android/obb/com.bethsoft.theelderscrollslegends/`.
5. Полностью останови игру через настройки Android и запусти её.
   Проверь экран подготовки, установку пакетов, запуск игры, русский язык,
   статистику, титулы, чат и кнопку Resources.
6. Переключение языка уже работающего Unity требует полного перезапуска
   приложения. Проверь явный язык и возврат к системному.

## Проверить передачу без кабеля

1. Собери отдельный результат с отключённым встраиванием языков.
2. В EXE выбери созданный каталог ресурсов, запусти сервер на LAN-адресе ПК.
   Разреши входящее соединение в брандмауэре для частной сети, если Windows
   спросит. Телефон и ПК должны находиться в доступной друг другу сети.
3. В Android-экране подготовки введи адрес и код. QR можно открыть внешним
   сканером: он передаёт их приложению; собственного сканера в игре нет.
4. Скачай язык, проверь запуск игры и остановку сервера через 60 секунд после
   подтверждения установки. Сервер также остановится после 15 минут простоя.
5. Для проверки именно скачивания выбери язык, которого ещё нет на телефоне:
   старый кеш сохраняется при обновлении APK. Не стирай все данные приложения.
6. Проверь прерывание передачи и повторную попытку. Для интернета нужен
   доступный HTTPS-адрес с корректным сертификатом; готовый туннель сборщик
   не создаёт. Сначала проверь локальную сеть.

## Что проверено здесь

- npm test: тесты JS и 15 тестов Python.
- Реальный Java PackInstaller: докачка, SHA-256, распаковка, квитанции,
  подтверждение установки, удаление языка, отклонение опасных путей/URL.
- Полная сборка синтетического XAPK: Android launcher/DEX, smali и ELF,
  подпись и zipalign, APK+OBB и XAPK со встроенными пакетами.
- Исходные файлы тестовой ПК-игры при сборке не изменяются.

Windows EXE должен впервые пройти сборку и smoke test в Actions. На настоящем
телефоне ещё нужно проверить Android-экран, локаль, интерфейс и реальные
ресурсы ПК-версии. Синтетический тест не подтверждает конвертацию всех
оригинальных игровых ассетов. Полный автоматический установщик новых APK
в эту версию не входит; существующее обновление JS-хука сохранено.

До этих проверок PR в upstream не отправляй. Если что-то упадёт, сохрани
`build.log`/`BUILD_FAILED.txt` из результата или лог Actions. Не публикуй
APK, OBB и пакеты игровых ресурсов в репозитории.
