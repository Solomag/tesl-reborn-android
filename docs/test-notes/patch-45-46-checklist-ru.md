# Патч 45 / APK 46 и синхронизация upstream

ZIP сохранить в E:\TESL-build. В WSL:

```bash
python3 -m zipfile -e /mnt/e/TESL-build/tesl-reborn-update-45-46.zip /mnt/e/TESL-build/update-45-46
bash /mnt/e/TESL-build/update-45-46/apply.sh
git -C ~/tesl-reborn-android-review push -u origin sync-upstream-and-ui-45-46
```

Скрипт создаёт отдельную ветку sync-upstream-and-ui-45-46 от текущего состояния
после 43–44. Основная ветка и её файлы не переписываются. В комплекте исходные
коммиты PR #1 и merge upstream (9c9fb7d) в git bundle. Сеть для их получения не нужна.
Затем выполняется обычное слияние. Девять заранее проверенных конфликтующих файлов
сохраняют нашу адаптированную реализацию; неизвестный конфликт останавливает скрипт.
Скрипт не делает reset, abort, force-push и ничего сам не публикует.

История upstream действительно становится предком новой ветки: это не просто
повторное применение патча. Уже перенесённые исправления авторизации, логов,
статистики и сборки сохраняются. Добавлены строгая проверка единственного Unity
bundle и защита путей в старом restore_cache.py; es_mx=3, ru_ru=8, tr_tr=9 сохранены.
В новом Builder эти языки/проверки уже были. Правила Git защищают hook.js от CRLF.

Push этой ветки запускает Build Desktop Builders. Скачать Builder из запуска
именно для sync-upstream-and-ui-45-46, собрать APK-only и установить поверх.
В APK 46 встроен патч 45. Старый feed в основной ветке пока остаётся на 43:
тестовая ветка не меняет обновления остальных телефонов. После проверки можно
слить тестовую ветку обратно и опубликовать OTA 45 обычным push основной ветки.

## Изменения интерфейса

Версия увеличена до 24 единиц, сделана светло-золотой и центрирована в области
под логотипом. Она видна только при распознанном экране загрузки, а в главном
меню и бою скрыта. Проверяются реальное имя активной Unity-сцены и активные
компоненты экрана загрузки. Не используется таймер «показать первые N секунд».
Распознавание конкретной сцены на телефоне нужно проверить; имя сцены и состояние
visible попадают в tesl-reborn-ui-status.json. Уведомления OTA остаются доступны
во время игры. Reborn API — версия совместимости, не онлайн-версия сервера.

Game Data снова имеет прежнюю ширину 180, а высота увеличена до 48. Кнопка сдвинута
в свободную область справа ниже полосы вкладок; текущий экран и другие настройки
не перестраиваются. Размер/место следует проверить на Pixel.

Предыдущая защита Cancel нашла 0 close hooks — это видно в присланном отчёте.
Теперь анализируется фактическое нажатие Unity Button.Press, имя кнопки и реальные
persistent callbacks внутри SettingsWin_Mobile. При Cancel/OK/Close наш фоновый
поиск перестаёт вмешиваться в закрывающееся окно. Оригинальные обработчики не
подменяются. Это исправляет отсутствие срабатывания старого guard; исчезновение
видимого моргания не подтверждено на устройстве. В журнале появится settings button.

Перед подключением к ПК проверяется наличие всех десяти установленных языковых
пакетов. Если все есть, показывается сообщение с Cancel и «Всё равно проверить ПК».
Без подтверждения сеть не используется. Это наличие локальных пакетов; без ПК
невозможно определить, подготовлены ли там более новые версии.

## Проверки

Прогнаны JS-тесты с реальным маршрутом Button.Press, скрытием версии в бою и меню,
сохранением уведомлений, а также 30 Python-тестов. Java/DEX и native JVM проверки
прошли, проверены подписанные синтетические APK всех трёх форматов. Слияние и его
установочный скрипт проверены отдельно, включая повторный запуск.

Видео подтверждает визуальный переход между окнами при Cancel; оно не доказывает,
что причина именно в Game Data. Ошибка изображений магазина этим обновлением не
объявляется исправленной. Реального Pixel и Windows EXE в среде нет.

## Свой main

Рекомендуемый следующий шаг после проверки — сделать текущий порт основой своего
main, а PR принимать уже туда. GitHub-форк может иметь собственный main и релизы;
удалять исходную историю или создавать пустой новый репозиторий ради этого не нужно.
Сохранить авторство исходной базы, Frederlk и лицензии сторонних компонентов.

Builder для Windows/Linux и обновления хука можно выпускать своими релизами.
Игровые ресурсы остаются на ПК пользователя. При смене URL update feed сохранить
совместимость со старыми APK: их зашитый адрес основной старой ветки нельзя просто
удалить. Сначала новый feed/проверка, затем новый APK, а старый feed продолжать
обслуживать. Переименование main и публикация релизов в этом обновлении не выполняются.
