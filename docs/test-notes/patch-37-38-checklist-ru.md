# OTA 37 и APK 38: версии, чёрный переход языка и диагностика

## Применение

Сохранить общий патч в E:\TESL-build и выполнить в WSL один раз:

```bash
cd ~/tesl-reborn-android-review
git am /mnt/e/TESL-build/tesl-reborn-android-37-38.patch && git push
```

Патч содержит manifest и payload OTA 37. Повторять publish_hook.py не нужно.

Для одной только версии/диагностики достаточно обновления по сети:
полностью остановить игру через сведения о приложении Android, запустить с
интернетом на 20 секунд, затем ещё раз полностью остановить и запустить.

Для чёрного перехода и ожидания завершения процесса нужен APK 38:

1. Дождаться успешного Build Desktop Builders на новом коммите, скачать Builder.
2. Выбрать прежние ПК-игру и оригинальный XAPK.
3. Expert mode… → APK only (keep installed game data) → Build APK only.
4. Установить полученный APK поверх. Не удалять приложение, языки или OBB.

## Что видно

Внизу экрана, включая загрузку, есть строка:

`Reborn API 1.3.1-beta · APK 38 · patch 37`

- patch — ревизия реально запущенного хука из загрузчика.
- APK — номер нативной сборки, записанный Android-частью. Старый APK, который не
  сообщает этот номер, показывается как legacy до установки новой сборки.
- Reborn API — версия совместимости порта (заголовок X-TeslRebornPlugin-Version).
  Это не подтверждённая версия работающего сервера и не обещание автоматического
  переноса нового PC DLL. Доступного подтверждённого источника версии сервера нет.

Подпись и уведомления используют встроенный шрифт Unity, а не языковые TMP-ассеты.
Они не перехватывают касания. Подпись остаётся и после исчезновения уведомления.

В OTA 36 отметка «уже показано» сохранялась до отрисовки. Теперь она сохраняется
только после успешного показа в следующем цикле UI; неудачная попытка не подавляет
сообщение на последующих стартах. Ошибки UI доступны в tesl-reborn-ui-status.json.
Это исправление установленного дефекта; без нового лога причина отсутствия
конкретной плашки OTA 36 на телефоне остаётся неподтверждённой.

## Смена языка

APK 38 объявляет отдельную LanguageActivity с чёрным стартовым фоном и ориентацией
игровой Activity. При наличии установленных ресурсов она не создаёт форму Game Data:
проверяет файлы на рабочем потоке и возвращает в Unity. Game Data и сканер сохраняют
свой обычный интерфейс. Если ресурсов нет или проверка не прошла, форма нужна для
исправления проблемы и будет показана.

Старый процесс Unity теперь сначала завершается, затем подтверждается его завершение
и только после этого запускается новая игровая Activity. Прежде запуск следовал сразу
после killProcess. Ожидание ограничено пятью секундами и выполняется вне UI-потока.
Запись языка, UI-выбор и проверка используют один захваченный вариант, без гонки
между асинхронным Android Spinner и параметром перехода.

Переход не полностью невидимый: остаются чёрный экран проверки и обычная загрузка
Unity. ОС ещё может показывать собственный значок запуска. Требуется проверка на
Pixel, что ориентация больше не скачет.

## Зависание на 70%, ClientHttpErrorUnknown и картинки магазина

ZIP установки распаковывается и проверяется до записи installed receipt; запуск
через Game Data дополнительно сверяет хеши common и выбранного языка. Поэтому
фоновая незавершённая ZIP-распаковка не подтверждена. Внутренняя обработка Unity,
проблема кэша, память и сетевые ответы требуют записи именно неудачного запуска.
Этот патч не объявляет зависание, изображения магазина или авторизацию исправленными.

Новая диагностика первые три минуты сохраняет последние 128 событий запросов
ассетов/HTTP, текущий язык/патч и ограниченные списки ключей словарей загрузки
AssetBundleManager. Нет тел HTTP, заголовков, паролей или токенов из URL.
Снимок обновляется не чаще раза в пять секунд и не изменяет/удаляет Unity-кэш.

Выбрать ещё не проверенный язык. Если зависло, подождать 10–15 секунд для снимка
и **до перезапуска игры** выполнить в PowerShell:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "\\wsl.localhost\Ubuntu-24.04\home\solo\tesl-reborn-android-review\tools\Collect-Resources.ps1" -Output "E:\TESL-build\resource-diag-loading"
```

Отдельно открыть магазин с отсутствующими картинками и сразу повторить:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "\\wsl.localhost\Ubuntu-24.04\home\solo\tesl-reborn-android-review\tools\Collect-Resources.ps1" -Output "E:\TESL-build\resource-diag-shop"
```

Если воспроизведётся ClientHttpErrorUnknown, собрать ещё один каталог с иным Output.
Передать содержимое этих каталогов. Не требуется tesl-login.json, игра или OBB.
Скрипт читает только перечисленные диагностические JSON, фильтрованный logcat
и память процесса игры. Очистка данных/кэша для диагностики не нужна.

## Проверки

JS/OTA и Python-тесты; отображение версии, подтверждение уведомлений после показа,
совместимость URI со старым APK, ограничение и очистка URL диагностики; Java→DEX;
JVM-тест завершения процесса/тайм-аута; синтетическая сборка, подпись и декодирование
тем для APK+ZIP, XAPK и APK-only. Оригинальной игры/телефона в среде проверки нет,
PowerShell-коллектор на Windows здесь не исполнялся.
