# OTA 39 / APK 40: отчёты с телефона, без ADB

## Установка общего обновления

Архив tesl-reborn-update-39-40.zip содержит предыдущий патч 37–38 и новый 39–40.
Сохранить ZIP в E:\TESL-build. В WSL:

```bash
python3 -m zipfile -e /mnt/e/TESL-build/tesl-reborn-update-39-40.zip /mnt/e/TESL-build/update-39-40
bash /mnt/e/TESL-build/update-39-40/apply.sh
git -C ~/tesl-reborn-android-review push
```

Скрипт проверяет историю: уже применённый 37–38 не повторяется. Если уже применено
всё обновление, он ничего не меняет. Незафиксированные изменения и незавершённые
операции Git требуют сначала проверки git status. Скрипт не делает reset, abort,
не удаляет локальные файлы и сам не отправляет изменения в сеть.

После успешного Build Desktop Builders скачать новый Builder, выбрать прежние
ПК-игру и оригинальный XAPK, затем Expert mode… → APK only (keep installed game data).
Установить APK поверх текущего. Пакеты языков и OBB переносить заново не нужно.
В нём Android 40 и начальный патч 39. Это одна необходимая установка APK для новых
Android-кнопок, ярлыка и штатного меню обмена файлами.

## Как отправить отчёт

1. После ошибки открыть Settings → Game Data.
2. Нажать Share diagnostic report / «Поделиться отчётом об ошибках».
3. На экране диагностики ещё раз нажать кнопку отправки, выбрать приложение
   (например ChatGPT или файловый менеджер) и прикрепить готовый ZIP.

Если игра зависла на загрузке и до Settings не добраться:

1. Вернуться на домашний экран Android, не перезапуская игру.
2. Долго нажать значок TESL → Diagnostics / «Диагностика».
3. Подготовить и отправить отчёт.

Ярлык регистрируется после первого запуска APK 40. Его видимость зависит от
поддержки быстрых действий лаунчером. На Pixel Launcher её требуется проверить
на телефоне; реального устройства в среде сборки нет. Диагностика работает в
отдельном от Unity процессе, не запускает Unity и не меняет выбранный язык.

Ничего не отправляется автоматически. Отчёт передаётся только приложению,
которое пользователь выбрал в Android Share. Можно отменить отправку.

## Что записывается

- Ошибки, предупреждения и исключения Unity через штатный log callback.
- События хука, результаты HTTP и состояния обновлений.
- Текущий язык, реальная ревизия патча, нативная версия, загрузка ресурсов,
  состояние передачи между Activity и доступные сведения о памяти игры.
- При доступности — ограниченный Android logcat своего UID. Работа основного
  журнала не зависит от доступа к logcat и не требует root или READ_LOGS.

Основной журнал хранится в приватных файлах приложения: текущий и два предыдущих
сегмента по 128 КиБ. Максимум 80 сообщений в секунду защищает от потока одинаковых
предупреждений. Отдельный журнал ошибок Android-части тоже ограничен. Последние
три сформированных ZIP хранятся в приватном кэше, старые удаляются при новом экспорте.

Тела запросов в постоянный журнал не записываются. Перед экспортом дополнительно
маскируются известные поля паролей/токенов, Authorization/Cookie и коды подключения.
tesl-login.json, прочие файлы аккаунта, OBB и игровые ассеты не читаются и в архив не входят.
Экспорт использует закрытый ContentProvider с временным разрешением только на
чтение конкретного готового отчёта, а не на весь каталог приложения.

Это журнал последних событий, а не полная запись всего телефона. При аварийном
завершении могут отсутствовать последние строки; системный native-crash stack
попадёт в ZIP только если Android разрешит прочитать его из logcat. Старые ошибки,
произошедшие до установки логгера, восстановить из нового журнала нельзя.

## Проверка

Открыть диагностику и поделиться отчётом без ошибок — ZIP должен читаться и содержать
device.json, диагностические JSON и logs/. Затем воспроизвести зависание нового языка
или пропавшие картинки и собрать отдельный отчёт до перезапуска.

Проверены ограничение журнала по UTF-8-байтам, ротация, маскирование и исключение
логина/больших файлов, создание ZIP, правила путей, manifest экспортного provider,
сборка Java/DEX и подписанных тестовых APK. Нативное меню «Поделиться» и ярлык
требуют проверки на телефоне. Зависание на 70%, магазин и авторизация этим
обновлением не объявляются исправленными.
