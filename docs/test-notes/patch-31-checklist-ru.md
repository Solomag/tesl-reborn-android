# Android 31 — область Ctrl+D, канал обновлений и сборка только APK

Патч поверх Android 30. Для области касаний и экранов настроек нужен новый APK.

## Известные проблемы Android 30

Пользователь подтвердил: при RU → EN настройки и загрузочный экран могут оставаться
русскими; кнопка Game Data была удалена из правильного окна вместо меню шестерёнки.
Логика размещения кнопки возвращена к Android 29, где доступ в правильных Settings
ещё был. Лишняя кнопка в меню шестерёнки пока может остаться. Языковой сбой
этот пакет не объявляет исправленным. Для точного исправления добавлен сбор
метаданных двух окон и фактического состояния локализации, без данных авторизации.
Перенаправление выбора языка в отдельный Android-список пока сохраняется.

После установки диагностического APK 31 запустить в PowerShell:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "\\wsl.localhost\Ubuntu-24.04\home\solo\tesl-reborn-android-review\tools\Collect-Settings.ps1" -Output "E:\TESL-build\settings-reports"
```

Скрипт попросит последовательно открыть меню шестерёнки, настоящие Settings,
затем воспроизвести смену на английский и снова открыть Settings. В каждом случае
нажать Enter в терминале. Передать три JSON из settings-reports. Они содержат
пути активных кнопок, имена обработчиков, выбранный/фактический язык и количество
строк в EN/RU-словарях; содержимое словарей и файлы логина не выгружаются.

## Применить

Сохранить tesl-reborn-android-31.patch в E:\TESL-build. В WSL:

```bash
cd ~/tesl-reborn-android-review
git am /mnt/e/TESL-build/tesl-reborn-android-31.patch && git push
```

GitHub Actions → Build Desktop Builders → новый Windows или Linux Builder.
В Game Data нового APK заголовок должен показывать Android 31.

## Собрать только APK

В Builder открыть Expert mode… → APK only (keep installed game data).
Языковые галки и обычные форматы станут недоступны. Нажать Build APK only и
подтвердить предупреждение. ПК-игра и оригинальный XAPK всё ещё выбираются как
исходники, но языковые пакеты не конвертируются и не формируются. OBB извлекается
во временную папку для проверки и расчёта метаданных; в output не копируется.

Результат — tesl-reborn.apk, журнал, build.json и небольшой пустой каталог
resources/catalog.json для существующего QR-сервера. OBB, пакетов языков,
ZIP с данными и XAPK в этом режиме нет. Start transfer может передать APK
через обычную страницу QR. Игровых данных в таком каталоге для скачивания нет.

Установить APK поверх существующего приложения. OBB, файлы приложения,
установленные языки и текущий выбор языка не удалять. На чистом телефоне
этого APK недостаточно: для него нужны игровые данные из обычной сборки.
Режим подходит для изменений кода; если патч требует новых ресурсов, их нужно
подготовить и установить отдельно обычной сборкой.

## Проверить Ctrl+D

После запуска игры в верхнем левом углу должна появиться полупрозрачная
фиолетовая область с рамкой и надписью 3x. Рамка совпадает с областью жеста.
Это Drawable поверх игровой Activity; он не получает и не поглощает касания.

Три коротких тапа внутри за 1,1 секунды: 1/3 → 2/3 → 3/3. На третьем область
становится зелёной и отправляется прежняя Android-комбинация Ctrl+D.
Проверить в меню и в бою. Повторить для скрытия debug-окна.

3/3 подтверждает распознавание жеста, а не появление debug-окна. Если счётчик
работает, а окно не меняется, искать нужно передачу клавиш/обработчик игры.
Разрешение debug остаётся серверным: патч его не выдаёт.

В Game Data → Advanced можно выключить Show Ctrl+D test area. После возврата
в игру рамка исчезнет; сам жест продолжит работать. Временная отметка включена
по умолчанию в этой тестовой сборке, пока мы проверяем координаты и доставку.

Для диагностики в PowerShell:

```powershell
adb shell cat /sdcard/Android/data/com.bethsoft.theelderscrollslegends/files/tesl-reborn-debug-status.json
```

marker-ready — рамка подключена; gesture-detected — распознаны три тапа;
android-ctrl-d-sent — отправлена последовательность клавиш, не подтверждение
срабатывания игрового debug-обработчика.

## Что и откуда обновляется

| Что | Где находится | Как обновляется |
|---|---|---|
| JS-код Android-порта | Начальная версия внутри APK, последующие — в приватных файлах приложения | Автоматическая загрузка с GitHub по манифесту |
| Java-установщик, QR-камера, Android-обработчик касаний, сам загрузчик | APK | Новый APK поверх старого |
| OBB, общие данные и языковые пакеты | ZIP данных / каталог resources; при XAPK часть данных упакована в его APK/OBB | Импорт ZIP или передача с ПК |

В XAPK программная часть остаётся внутри вложенного APK. В tesl-reborn-data.zip
код OTA не складывается: это архив игровых ресурсов.

runtime/channel.json теперь — единый источник адреса для встроенного загрузчика
и Builder. Этот файл добавлен в пакет EXE. Канал текущей тестовой ветки:

https://raw.githubusercontent.com/Solomag/tesl-reborn-android/android-ui-and-update-loader/updates/test/manifest.json

LaunchActivity и Game Data заполняют пустой старый feedUrl перед запуском Unity.
Непустой пользовательский канал, enabled=false и safeMode=true сохраняются.
Game Data → Advanced содержит Automatic patch updates, последнюю доступную
версию/состояние и адрес канала. Изменение переключателя вступает в силу после
полного перезапуска процесса игры. При safeMode=true обновления не проверяются.

Через 10 секунд после завершения инициализации hook игра делает HTTPS-запрос
манифеста. Проверяет ревизию, совместимость с loader API/ABI/версией игры,
скачивает указанный JS с того же HTTPS-origin, сверяет размер и SHA-256 и
атомарно сохраняет. Новый код применяется при следующем запуске процесса.
ADB, кабель и ПК для этого не нужны. SHA-256 проверяет соответствие кода
манифесту; доверие к самому коду определяется выбранным GitHub-каналом.

Проверка выполняется один раз за запуск. Сетевую ошибку повторяет следующий
запуск. Во время игры код на лету не заменяется. Если новый hook не завершил
инициализацию до следующего старта, загрузчик отвергает его и выбирает доступную
предыдущую/встроенную версию. Это не обнаружение всех возможных ошибок интерфейса.

Важно: обновление hook.ts или runtime/core.js в Git само по себе не публикует OTA.
Нужно подготовить манифест и payload, затем закоммитить и запушить updates/.
В этом патче новый OTA-релиз не публикуется; старый канал с ревизией 24
для встроенной версии 31 даст up-to-date без понижения версии.

## Проверить настоящую загрузку обновления

После установки и проверки APK 31 можно подготовить тестовую ревизию 32.
В WSL из репозитория:

```bash
npm run build
python3 tools/publish_hook.py --revision 32 --version android-32-ota-test --channel test --base-url https://raw.githubusercontent.com/Solomag/tesl-reborn-android/android-ui-and-update-loader/updates
git add updates
git commit -m "Publish Android OTA test 32"
git push
```

Если ревизия 32 уже занята, выбрать следующую свободную. Скрипт не меняет
Java-код и не собирает новый APK. updates/test/manifest.json указывает на
updates/payloads/<sha256>.js. Материалы оригинальной игры туда не добавляются.

Запустить игру с интернетом, подождать проверки. В Game Data появится сообщение
о скачанном обновлении. Для надёжного перезапуска остановить приложение через
настройки Android → Force stop, затем открыть. Смахивания из недавних может быть
недостаточно. В update-status current.revision должно стать 32, pending — null.
В этом тесте код 31 и 32 одинаков, поэтому SHA может совпасть; проверять ревизию.

## Проверки

Пройдены: npm test (включая 23 Python-теста), сборка Java → DEX,
JVM-тесты миграции пустого канала с сохранением отключения/safe mode/своего URL,
счётчика касаний, SHA и установки ресурсов. Синтетическая полная сборка
проверяет три режима (APK+ZIP, XAPK, APK-only), подпись и передачу APK по Range.
Отдельно проверена загрузка core с кириллицей/эмодзи без legacy unescape().

Локально доступны синтетические входные APK/XAPK и настоящие SDK/подпись,
но нет Pixel и оригинальной игры. Поэтому видимость рамки поверх Unity,
поведение Windows GUI и фактическое появление debug-окна требуют проверки
на устройстве. Загрузка APK при плохой сети этим патчем не исправляется.
