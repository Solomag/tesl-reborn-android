# OTA 41 / Builder и APK 42

## Применение

Сохранить tesl-reborn-update-41-42.zip в E:\TESL-build. В WSL:

```bash
python3 -m zipfile -e /mnt/e/TESL-build/tesl-reborn-update-41-42.zip /mnt/e/TESL-build/update-41-42
bash /mnt/e/TESL-build/update-41-42/apply.sh
git -C ~/tesl-reborn-android-review push
```

Это обновление поверх 39–40. Скрипт проверяет историю и не применяет патч повторно.
При незавершённом git am или изменённых отслеживаемых файлах он останавливается,
не выполняет reset/abort и ничего не удаляет. Сам push скрипт не выполняет.

После push OTA 41 готов к получению телефоном из прежнего test feed; применение
после полного перезапуска игры. Для изменений Builder скачать новый артефакт
Build Desktop Builders. APK-only позволяет сохранить установленные ресурсы.
Установить новый APK 42 поверх текущего — он также содержит патч 41 и расширяет
экспорт журнала. OBB, ZIP и языки переносить заново не нужно.

## Builder

- Режим эксперта — галочка справа сверху. Только при её включении видны APK only
  и дополнительные настройки связи.
- APK only очищает и блокирует выбор языков и формата, показывает пояснение.
  При возврате прежние языки и язык по умолчанию восстанавливаются.
- Примечания, подписи сети и окна QR переведены на все десять языков интерфейса.
  Технические ошибки и журнал остаются техническим текстом.
- «Остановить» и «QR и подключение» появляются после запуска сервера. На время
  запуска/работы сервера повторный старт и смена выбранной сборки блокируются.
- «Скопировать подключение» находится в отдельном окне QR, которое можно открыть
  повторно. После остановки сервера это окно закрывается.
- «Передать готовую сборку…» выбирает папку конкретной сборки из output и позволяет
  снова передать уже подготовленные файлы без повторной сборки.
- Загрузка APK пишет начало, запрошенный диапазон/докачку, прогресс раз в три
  секунды, скорость и завершение либо обрыв. Журнал виден в Builder и сохраняется
  в transfer.log в выбранной папке результата. URL с временным кодом не пишется.
  «Файл отправлен» означает передачу сервером: это не подтверждение установки APK
  телефоном. HEAD-запросы не считаются скачиваниями.

## Что показала присланная диагностика

Архив собран на APK 40 с патчем 39. Во всех трёх сохранившихся запусках уведомления
падали на `Canvas.set_renderMode`: метод отсутствует в управляемых метаданных
мобильного Unity 2017.4. Поэтому подпись версии и уведомления не показывались.

В патче 41 Canvas использует доступный managed-метод либо проверенный через
il2cpp_resolve_icall нативный accessor. Если отсутствует и native binding, только
наш объект добавляется к активному Canvas игры. Игровые объекты не клонируются
и не перемещаются. CanvasScaler/CanvasGroup с потенциально вырезанными setters
не нужны; размер рассчитывается по экрану. Текст предпочитает встроенный Arial,
а при отсутствии legacy API использует уже работающий в игре TMP. Нет кнопок,
GraphicRaycaster или перехвата нажатий у версии/уведомления.

Название `Español Mexicano` на втором скриншоте не входило в таблицу псевдонимов.
Теперь распознаётся непосредственно как es_mx. Проверены реальные подписи всех
десяти языков: нативный обработчик смены с выходом из аккаунта подавляется, а
сохраняется тот же короткий чёрный переход с применением выбранного языка.

Немецкий запуск записал access violation при восстановлении локализации. В коде
было окно для сборки мусора: словарь из 15 тысяч строк ещё не принадлежал менеджеру
игры и заполнялся без GC handle. Теперь он удерживается сильной ссылкой до полной
привязки к менеджеру, включая plugin-строки. Ошибка больше не помечается как удачное
восстановление. Это исправляет конкретный дефект; повторную проверку DE на телефоне
всё равно нужно выполнить.

## Cancel и пустой главный экран

Добавлен guard закрытия Settings: при доступных нативных Cancel/Close/Hide/OnDisable
наш Game Data скрывается, и фоновая проверка не включает его заново до открытия
окна. Оригинальные callbacks не подменяются, сохранение или откат настроек остаётся
за игрой. Их названия и срабатывания записываются в журнал. Это исправление
взаимодействия нашего контрола с закрывающимся окном; конкретный визуальный эффект
Cancel ещё требуется проверить на телефоне.

Причина пустого главного экрана на первом скриншоте **не установлена**. Есть ошибки
Unity `Material doesn't have a texture property '_MainTex'`, но сами по себе они
не доказывают причину отсутствия меню или картинок магазина. Ошибка входа именно
при мексиканском переключении в сохранённые три последних запуска не попала.
Сохранившиеся запросы входа и загрузки аккаунта завершились успешно; ошибки
config.uca/cdp.cloud.unity3d.com относятся к Unity analytics.

Для следующего случая добавлены снимки состояния MainMenu/MainMenuNavComponent
и их прямых детей в tesl-reborn-resource-status.json. Никакого автоматического
сброса аккаунта, кеша или принудительного переключения сцен нет.

APK 42 экспортирует текущий и девять предыдущих сегментов журнала по 128 КиБ,
чтобы пройти все языки и не потерять первый проблемный запуск. Без APK 42 OTA
уже сохраняет расширенную историю, но старый экспортер отдаст только прежние три
сегмента. Правила маскирования и запрет включения сохранённого логина прежние.

## Проверка на телефоне

1. После обновления проверить подпись APK/patch и уведомление о применении OTA.
   `Reborn API 1.3.1-beta` — версия совместимости порта, не онлайн-версия сервера.
2. EN → Español Mexicano → DE → EN: язык меняется без ручного выбора и ввода пароля.
3. Settings → Cancel, открыть снова; затем OK и открыть снова. Game Data остаётся
   в полноценном Settings, а не в меню шестерёнки.
4. Если пустой главный экран повторится, не перезапускать игру: домашний экран
   Android → долгое нажатие на значок игры → Diagnostics → отправить ZIP.

## Что проверено здесь

JS-тесты выполняют resolver названий языков, удержание словаря, renderer с вырезанным
Canvas setter/native binding и передачу OTA через прежний loader API 1. Python-тесты
проверяют состояния формы и все каталоги переводов без графического дисплея;
HTTP-тесты реально обрывают соединение и затем получают диапазон APK. Также
проверены Java/DEX, native JVM-тесты и сборка/подпись/проверка синтетических APK
трёх форматов. Оригинальной игры и телефона в этой среде нет; Windows EXE и
визуальное поведение на Pixel нужно проверить через Actions и устройство.
