# Builder / APK 44 и патч 43

Сохранить tesl-reborn-update-43-44.zip в E:\TESL-build, затем в WSL:

```bash
python3 -m zipfile -e /mnt/e/TESL-build/tesl-reborn-update-43-44.zip /mnt/e/TESL-build/update-43-44
bash /mnt/e/TESL-build/update-43-44/apply.sh
git -C ~/tesl-reborn-android-review push
```

Обновление поверх 41–42; скрипт пропускает уже применённый патч, не делает reset,
abort или push. После Actions скачать новый Builder. Для исправления передачи APK
достаточно нового Builder: старый телефон сможет открыть новую страницу QR.
Для отмены подключения в Game Data нужен новый APK 44, установленный поверх.
Формат «только APK» сохраняет игровые данные, языки и OBB.

## Передача APK

Прежний QR открывал обычную ссылку загрузки браузером. Сервер поддерживал Range,
но не контролировал, какой итоговый файл сохранил браузер. Присланный лог показывает
обрывы и докачки; он не устанавливает, по какой причине браузер сохранил битый файл.

Теперь страница загружает APK диапазонами по 256 КиБ. Проверяет HTTP 206, точный
Content-Range, ETag и размер каждого принятого фрагмента. Оборванный фрагмент не
сохраняется. До восьми повторов фрагмента с паузами; доступна кнопка Pause.
Готовые фрагменты сохраняются в IndexedDB по SHA-256 файла и смещению. Повторное
нажатие Download / resume продолжает загрузку. Если браузер запрещает IndexedDB,
используется память текущей страницы: закрытие страницы теряет такую докачку.
При смене порта ПК нужен новый QR; фрагменты того же SHA-256 можно использовать
снова в пределах того же browser origin. Другой origin имеет отдельное хранилище.

После загрузки выполняется полный SHA-256, а не только проверка размера. Только
при совпадении появляется Save verified APK. Нажать её, затем открыть файл в
Downloads и установить. Проверка работает и по локальному HTTP: WebCrypto/HTTPS
не требуются. При несовпадении хеша сохранение блокируется и фрагменты этого файла
удаляются. Обычная прежняя ссылка, обходившая проверку, с основной страницы убрана.

Проверка хеша обнаруживает повреждение передачи относительно данных Builder.
Это не независимое подтверждение происхождения APK. Browser Blob/скачивание
на конкретном Android-браузере ещё нужно проверить на телефоне. Во время сборки
тестируется точное содержимое итогового Blob, включая обрывы и повреждение.

## Game Data

Получение каталога больше не повторяется восемь раз по старому адресу. Одна попытка:
5 секунд на соединение, 8 секунд на ожидание чтения. На время запроса есть Cancel;
Android Back тоже отменяет запрос каталога. Отключение соединения выполняется
вне UI-потока. При неудаче можно сразу сканировать новый QR, без закрытия приложения.
Выбор языков открывается уже после снятия busy: быстрая кнопка Download больше
не теряется из-за порядка двух UI-callbacks.

Это отмена подключения за каталогом; отмена распаковки/установки больших пакетов
этим изменением не добавляется. Нет очистки аккаунта или игровых ресурсов.

## Settings и магазин

Game Data увеличена с 180×28 до 240×42 единиц UI. При Cancel мы больше не меняем
SetActive её объекта: она закрывается вместе с родительским нативным окном.
Guard всё ещё предотвращает вмешательство фонового поиска в закрывающееся окно.
Нужно проверить, исчезло ли моргание на телефоне; оригинальные callbacks не заменены.

Новый отчёт подтверждает APK 42 / patch 41 и видимую подпись версии. Запросы
shop/fetchCatalog успешны (200). В Unity есть Material doesn't have a texture
property '_MainTex'. Ни эти ошибки, ни HTTP 200 не доказывают причину отсутствия
изображений паков. Изображения могут ссылаться на отдельные URL или локальные
ассеты. Подмена шейдеров или скачивание случайных ресурсов не выполняются.

Для расследования добавлен shopImages в tesl-reborn-resource-status.json: пути
активных Image в магазине, имя sprite/material/shader, без текста аккаунта.
Диагностика ресурсов теперь действует первые 15 минут, чтобы успеть зайти в магазин.
После установки открыть проблемную вкладку магазина, подождать 6 секунд и отправить
отчёт сразу, оставаясь на ней. Отсутствующие картинки пока не объявляются исправленными.

## Проверки

Проверены SHA-256 на граничных размерах блоков и случайных данных, правильность
итогового APK Blob, повтор после сброса, повторное использование фрагментов,
отклонение неправильного Range и блокировка сохранения при повреждении. Также
проверены серверные HTTP-тесты, JS/UI regression, Java/DEX, native JVM и сборка
подписанных синтетических APK всех трёх форматов. Реального Pixel и Windows EXE
в этой среде нет; окончательное поведение браузера и кнопки отмены проверяется
после Actions на устройстве.
