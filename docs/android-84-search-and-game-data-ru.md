# Android 84: поиск колод сразу и меню Game Data в стиле игры

## Поиск колод (OTA 84, `android-84-instant-deck-search`)

Отчёт 29: поиск появлялся заметно позже списка колод, а пока список открыт,
каждые 250 мс шло сканирование на 100–130 мс (`scheduled task slow … (deck
search scan)`).

- Строка поиска ставилась только опросом, и `uiRetryGate` впервые пропускал
  установку через 500 мс после того, как окно было замечено: до ~0,75 с плюс
  асинхронная загрузка рамки. Теперь она ставится сразу из
  `DeckPickerWin.UpdateUi` — игра вызывает его, когда сетка колод заполнена
  (`deck search: installed with the deck list`). Опрос с прежним шлюзом остался
  запасным путём.
- Загруженные нативные спрайты (рамка поля, крестик) кэшируются: со второго
  открытия они появляются в том же кадре.
- Обход всех колод выполняется только если есть что менять: непустой запрос,
  скрытые колоды, которые нужно вернуть, или изменившийся набор колод при том
  же запросе. Пустое поле больше не стоит 100+ мс каждые 250 мс.

## Лаги в бою

В бою отчёта 29 (18:07:44–18:14) самая длинная остановка — 1,5 с без задач
хука; остальные 200–500 мс — с задачами короче 100 мс. Это поведение самой
игры, а не хука.

## Меню Game Data и диагностика (лаунчер, нужна пересборка APK)

`ResourceActivity` и `DiagnosticsActivity` используют общий `UiStyle`: тёмный
фон окон игры, золотой заголовок с засечками, золотые основные и контурные
второстепенные кнопки, размеры в dp, колонка по центру шириной до 640 dp
(ширина ограничивается при каждом измерении — экран обрабатывает поворот сам).
Вверху Game Data — версия: `TESL Reborn · APK N · patch M`.
Внешний вид проверяется только на устройстве.
