# OTA 58: первое открытие интерфейса после обновления

Требуется OTA 57. Пересборка APK, OBB и языков не нужна.

## Что показал отчёт до перезапуска

В присланном `tesl-reborn-report.zip` предварительный загрузчик имеет статус
`staged`, а основной загрузчик уже запустил 57, вызвал `ready` и очистил `pending`.
Текущий SHA-256 — `21872ed75431f15238b2bbdcda343fcd7848b32344db6dd3ce3c7d2d191028e7`.
Ошибок проверки размера/хеша или отката этой версии нет. Старая отменённая
проверка обновлений в native.log относится к другому запуску.

После входа поиск выдаёт `access violation accessing 0x0` каждые 250 мс,
без сообщения `deck search: installed`. Старая реализация оставляла частично
созданный видимый объект и заново создавала его при следующем опросе.
Это объясняет мигание. При построении статистики также встречается
`Unsupported deck-name renderer: BestHTTP.SignalR.Hubs.OnMethodProgressDelegate`:
вместо текстовой компоненты прочитан посторонний тип.

Вероятна проблема времени жизни управляемых объектов при холодной инициализации:
JS-обёртка с указателем не является сильной ссылкой для сборщика мусора IL2CPP.
Это гипотеза по признакам; отчёт сам по себе не доказывает точную причину
неверного указателя. Повторный запуск той же 57 заработал без новой загрузки.

## Исправление

- Управляемые объекты удерживаются сильными GCHandle во время конструктора,
  добавления в UI и первоначального поиска шрифта. Временные ссылки освобождаются
  в `finally`, включая неудачные попытки.
- При создании статистики заранее проверяется семейство текстового рендерера;
  исходный текст, шрифт и новые компоненты удерживаются до завершения создания.
- Поиск ждёт 500 мс после появления активного окна. Поле скрыто, пока его текст,
  ввод и кнопка очистки не созданы полностью.
- При ошибке частичное поле удаляется, отступ списка восстанавливается. Повторы
  идут с паузами 1 и 2 секунды, максимум три попытки за открытие окна. Затем можно
  закрыть и открыть выбор колоды — клиент перезапускать для новой попытки не нужно.
- Ошибка перечисления окон больше не трактуется как закрытие окна и не удаляет
  уже работающий поиск. Массивы окон и плиток удерживаются во время обхода.
- В лог записываются номер попытки и этап: root, create bar, text/input,
  placeholder, clear button.

Формат и код транспортного загрузчика API 1 не менялись: размер, SHA-256,
сохранение payload перед указателем состояния и применение перед Unity уже
проверяются существующим механизмом. `ready` означает установку перехватчиков;
это не проверка всех окон, которые игрок откроет позже. Отложенное создание UI
теперь обрабатывает собственные ошибки, вместо бесконечного пересоздания.

## Проверка

`npm test` включает запуск настоящего обработчика поиска с подставными Unity API:
ошибка во время создания InputField, удаление незавершённого поля, восстановление
отступа, освобождение GCHandle, пауза и успешная следующая попытка, предел трёх
ошибок и восстановление после повторного открытия окна. Отдельно проверяются
сильные ссылки в конструкторе, при добавлении UI и холодном поиске шрифта,
включая выходы по исключению. Это проверка логики, а не запуск IL2CPP на телефоне.

После публикации полностью закрыть и открыть игру с подключением к сети.
На первом запуске с версией 58 сразу открыть выбор колоды: проверить подсказку,
набор текста, очистку, статистику, закрытие и повторное открытие. Если проблема
повторится, сохранить диагностику именно до перезапуска — этапы ошибок теперь
различимы. Автоматическое отсутствие любых ошибок первого запуска на реальном
Android здесь не подтверждено.
