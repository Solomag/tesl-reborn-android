# Android 29 — докачка, несколько языков и Android Ctrl+D

Патч поверх Android 28. Требуется новая сборка APK: изменены нативный установщик
и обработчик касаний оригинальной игровой Activity. Сохранённые данные игры,
OBB и уже установленные языки удалять не нужно.

## Получить новый Builder

Сохрани tesl-reborn-android-29.patch в E:\TESL-build. В WSL:

```bash
cd ~/tesl-reborn-android-review
git am /mnt/e/TESL-build/tesl-reborn-android-29.patch && git push
```

GitHub Actions → Build Desktop Builders. Workflow собирает два артефакта:

- TESL-Reborn-Builder-Windows — EXE с Java и инструментами;
- TESL-Reborn-Builder-Linux-x86_64 — tar.gz с исполняемым сборщиком, Java и
  инструментами. Linux-сборка создаётся на Ubuntu 22.04; ориентир — совместимые
  настольные системы x86_64 с glibc 2.35 и новее. ARM и Alpine/musl не заявлены.

На Linux распакуй архив, открой TESL-Reborn-Builder или запусти в терминале:

```bash
chmod +x TESL-Reborn-Builder
./TESL-Reborn-Builder
```

Интерфейс и форматы результатов одинаковые. Нужна настольная графическая сессия.
EXE Windows в Wine для этого не требуется. Сборщик не меняет файлы исходной игры.

В self-test.json ожидается core=android-29-resume-and-native-input. CI проверяет
Linux GUI через Xvfb. Локальная проверка замороженного приложения без экрана
отмечается guiTested=false и не заменяет проверку окна на настоящем рабочем столе.

Новый Builder не меняет старые APK автоматически: собери новый APK с прежними
ПК-игрой и оригинальным XAPK. Для проверки достаточно английского и русского.
Установи APK поверх существующей игры. Для первого получения нового APK по QR
используй обычную камеру → Download APK. Кабель для обычной установки не нужен.

## Передача при нестабильной сети

Приложение сохраняет недокачанный файл по SHA-256 в .part. После сетевого обрыва
или таймаута оно повторяет запрос с Range от последнего сохранённого байта.
Задержка между попытками растёт с 1 до 15 секунд. Если данные продолжают приходить,
серия неудач сбрасывается. После 20 последовательных неудач без прогресса выводится
ошибка с сохранением частичного файла: повторное Download продолжает его.
Закрытие установщика также не удаляет .part. Частичные файлы хранятся в постоянной
приватной папке приложения, а не в очищаемом Android cache; старые .part из
Android 28 переносятся при открытии Game data. Готовый файл проверяется по SHA-256
перед установкой. Уже установленные отдельные пакеты сохраняются.

Для чтения сети установлен таймаут 90 секунд. Повторяется и получение небольшого
каталога. Ошибки доступа, отсутствующий файл, неправильный диапазон/размер и нехватка
места не маскируются бесконечными сетевыми повторами.

Сервер теперь поддерживает HEAD, стабильный ETag по содержимому, Last-Modified,
If-Range, диапазоны и корректное завершение HTTP-ответа. При изменившемся ETag
возвращается полный файл, чтобы клиент не склеивал разные версии. Это относится
и к APK, и к APK внутри XAPK. Незавершённый ответ не остаётся открытым как
успешный keep-alive ответ. APK не подтверждает завершение установки ресурсов.

Повторы в самом Android-установщике контролирует наше приложение. Поведение
повторов скачивания APK через браузер зависит также от браузера/Download Manager;
браузерный APK нельзя считать проверенным только по наличию файла в Downloads.
Размер и содержимое конечного APK должны соответствовать оригиналу сборки.

Не перестраивай комплект и не закрывай Builder во время докачки. Если сервер
пришлось перезапустить, отсканируй новый QR; для того же подготовленного комплекта
частичные файлы на телефоне сохраняются и подходят для продолжения.

## Выбор языков

Галочки на ПК определяют, какие языки доступны для установки. Раньше сеть всегда
забирала только текущий игровой язык. Теперь Download missing game data открывает
список подготовленных языков с галочками и двумя действиями:

- Download selected — скачать отмеченные;
- Download all — скачать все подготовленные на этом ПК.

Общие ресурсы и OBB добавляются по необходимости. Выбор сохраняется, а успешно
установленные пакеты не скачиваются заново, если их хеш совпадает с каталогом.
В Offline XAPK все встроенные языковые пакеты устанавливаются вместе при первой
подготовке. Импорт data ZIP, как и раньше, устанавливает все включённые языки.

Проверь EN+RU: обе галочки → обе установки → русский доступен в Game data.
Режим скачивания пакетов и текущий язык игры — разные настройки: можно хранить
несколько пакетов и играть на одном языке.

## Смена языка из штатных Settings

Подтверждено пользователем до Android 29: через Game data смена работает, через
штатные Settings — нет. Поэтому отсутствие русского пакета и обработка штатного
выбора рассматриваются отдельно.

Добавлены перехватчики языка в setter-методах игровых профилей/настроек, а не
только в классах с именем Settings. Для стандартных Unity/TMP-списков язык
определяется по подписи выбранного пункта, а не по предполагаемому номеру языка.
Инициализация списка без уведомления не считается выбором пользователя.
Выбор должен передаваться в тот же установщик
с применением выбранного пакета и чистым запуском игры. Настройка языка сервера
согласуется в auth-запросах и URL, а пути локализации — с выбранным кодом.
Поздняя подмена словаря новым объектом больше не должна сохранять словарь
предыдущего языка только потому, что число записей ненулевое.

В нормализаторе auth JSON также устранена зависимость от escape/unescape, которых
нет в используемом JS-окружении. Unicode-данные сохраняются без изменения.
Отказ входа при перезапуске больше не удаляет ранее успешно сохранённый пароль.
Это не гарантирует успех входа при недоступном сервере или изменённом пароле;
автоматическая попытка по-прежнему ограничена одной на процесс.

Проверка: EN → RU → EN именно из игровых Settings. Проверить не только настройки
и экран загрузки, но и главное меню, коллекцию и названия карт. Сначала убедись,
что оба пакета установлены через Game data. Для настоящего Android-клиента
работу этой привязки ещё требуется подтвердить: локальные тесты используют
синтетические объекты, а не оригинальную игру.

## Ctrl+D

Работа внешних Android-кнопок подтвердила, что штатный обработчик игры существует.
Новый жест обрабатывается в оригинальной Android Activity до передачи касания
игре. Три коротких тапа в верхнем левом углу примерно за секунду отправляют
обычные Android KeyEvent: Ctrl down → D down → D up → Ctrl up. Ctrl удерживается
между событиями и несколькими кадрами; используется тот же путь dispatchKeyEvent,
что и для физических/внешних клавиш.

Права сервера и обработчик дебага игры не изменяются. Уведомлений и видимой кнопки
нет. Прежняя JS-имитация отключается для APK с новым нативным обработчиком, чтобы
не получать два переключения подряд. Обычная обработка касания игры сохраняется.

Проверь показ и скрытие в меню и в бою. Если реакции нет, диагностический файл:

```powershell
adb shell cat /sdcard/Android/data/com.bethsoft.theelderscrollslegends/files/tesl-reborn-debug-status.json
```

Ожидается backend=android-key-events и status=android-ctrl-d-sent после жеста.
Это подтверждает отправку событий, а не наличие серверного права на дебаг.

## Game data и камера

Game data добавляется только в окно с настоящими настройками — активными
ползунками/переключателями/списками. Меню быстрых действий и корни Menu исключены.
Проверь: в меню до настроек кнопки нет, внутри настроек одна.

TextureView уже учитывает ориентацию сенсора. В Android 28 она применялась ещё
раз. Теперь добавляется только поворот устройства и равномерное кадрирование.
Первый запуск камеры и чтение QR нужно проверить на Pixel; новая математика
покрыта проверками, но живой камеры в среде разработки нет.

## Выполненные проверки

- JS: вход, Unicode-нормализация, локализация, UI чата/статистики/эмодзи и OTA.
- Python: HTTP HEAD/Range/If-Range, APK/XAPK, установка ресурсов и сохранение
  оригинального обработчика dispatchTouchEvent при патче smali.
- JVM: реальный PackInstaller переживает искусственно оборванный ответ и сам
  продолжает с нового смещения; установка, хеши, архивы, QR, геометрия и три тапа.
- Компиляция Android DEX, сборка и подпись синтетических APK+ZIP и XAPK с новым
  вызовом GestureBridge. Исходные файлы игры остаются неизменными.

Живую работу штатного переключателя языка, KeyEvent в Unity и камеры нужно
подтвердить на телефоне. Браузерную докачку при реальных сбоях провайдера тоже
следует проверить отдельно от искусственных HTTP-обрывов.
