Требуется применённый 45–46. Скрипт применяет 47 к sync-upstream-and-ui-45-46,
затем только fast-forward переносит основную рабочую ветку android-ui-and-update-loader
на её состояние. Если ветки разошлись, ничего не перезаписывает и останавливается.
Сам push не выполняет. Main репозитория, default branch и настройки GitHub не меняет.

GitHub перед изменением показал:
- android-ui-and-update-loader: 21 ahead, 5 behind upstream/main;
- sync-upstream-and-ui-45-46: 24 ahead, 0 behind;
- sync относительно android-ui-and-update-loader: 8 ahead, 0 behind.

Поэтому прежний счётчик действительно относился к старой ветке. После её
fast-forward и push она тоже включает upstream merge 9c9fb7d и не отстаёт от него.
В неё попадёт и updates/test/manifest.json 47: это тот адрес, который уже зашит
в телефоне. Новый APK для этих изменений не нужен. Полностью перезапустить игру
для проверки обновлений, после скачивания перезапустить ещё раз для применения.

## По новому отчёту

На телефоне APK 46 / patch 45. Распознавание загрузки работает: скрин показывает
версию на загрузке, а снимок из меню — visible:false. Но подпись попала на слово
LEGENDS. В 47 она находится на 30% высоты от нижнего края экрана, ниже логотипа
и выше полосы загрузки по присланному скриншоту; центрирование сохранено.

Game Data была ниже полосы вкладок. Её правый отступ и ширина 180 сохранены,
верхний отступ уменьшен с 136 до 74 единиц UI. Высота остаётся 48. Это поднимает
кнопку в свободную область справа от Preferences без увеличения ширины.

В журнале повторяется ошибка отсутствующего GetPersistentEventCount у
UnityEngine.UI.Button.ButtonClickedEvent. Она прерывала обработку Cancel раньше,
чем читалось имя кнопки. Теперь имя читается первым, а сведения о persistent
callbacks необязательны. При вырезанных API читаются только идентифицированные
через реальные метаданные поля PersistentCallGroup/списка/имени метода. Если и
они недоступны, остаётся распознавание имени кнопки и пути внутри Settings.
Повторный SetActive(true) уже активной кнопки больше не выполняется при опросе.

Это исправляет подтверждённую ошибку обработчика. Нельзя по одному этому заключить,
что моргание при Cancel исчезло: визуальный результат нужно проверить на телефоне.
Следующий отчёт должен содержать settings button / settings UI вместо ошибки
GetPersistentEventCount. Если моргание останется, эти записи покажут реальный
callback и его привязку; оригинальный Cancel не заменён другой кнопкой или OK.

JS-проверки воспроизводят вырезанную introspection API и распознавание Cancel,
проверяют положение версии и её скрытие в бою/меню. Полный набор и 30 Python-тестов
прошли. Java/DEX не менялись. Проверка установочного патча выполняется на отдельной
ветке; слияние основной ветки только fast-forward, без reset/rebase/force.
