# OTA 72: кнопка друзей и горячие пути

Требует 71. Пересборка APK/OBB/языков не нужна: полностью закрыть игру, запустить через значок, в футере `patch 72`.

## Друзья после поиска

Фикс 71 возвращал `interactable` одним замером в тот момент, когда окно поиска закрывается. К этому времени главное меню ещё неактивно: проверка `activeInHierarchy` давала ложь, писалось значение, снятое на момент поиска (`false`), и больше оно не переписывалось — кнопка оставалась нажимаемой только на бумаге. Тест 71 закреплял именно это состояние.

Теперь восстановление родителей, порядка, RectTransform и `activeSelf` выполняется сразу, как раньше, а для кнопки дополнительно запускается отложенный повтор: каждые 500 мс (до 30 с) проверяется, стал ли родитель меню активным; как только стал — `SetActive(true)` и `set_interactable(true)`, и ещё три повтора с интервалом 500 мс, чтобы перебить позднюю команду самой очереди. Держатся только три корня (кнопка, её родитель, GameObject), после завершения они освобождаются. Если объект умер, повтор останавливается.

## Подтормаживание розыгрыша

Причина на устройстве не доказана: свежего logcat нет. Статически убраны три дорогих места, которые попадают в игровой цикл:

1. **Отчёт по хешам бандлов.** Секция `bundle hash report` перебирала `GetAllAssetBundles`, для каждого имени считала `GetAssetBundleHash` и `ToString` и писала файл — на каждом вызове `AssetCatalog.SetCacheExpiration`, то есть в нормальном пути загрузки ассета. Теперь отчёт пишется один раз за сессию; пока манифеста нет, повтор раз в 60 с и максимум три попытки. В лог добавлена длительность: `bundle hashes: wrote N entries … in Nms`.
2. **Чтение языка на каждой загрузке ассета.** Секция `localization asset trace` читала `tesl-reborn-language.json` для любого пути; теперь только для `/Localization/Text/` и `/Localization/Audio/`.
3. **Четыре чтения файла языка на один `LocalizationManager.UpdateObjects`.** Осталось одно.

## Пробник зависаний

Новая секция `main loop stall probe`: разрыв между двумя `ServicesManager.Update` длиной от 400 мс до 60 с даёт строку `main loop stalled Nms` в `adb logcat -s tesl-hook:I` и в порт-логе (`/data/user/0/com.bethsoft.theelderscrollslegends/files/tesl-reborn-logs`), не чаще раза в секунду. Фоновые перерывы (свёрнутая игра) не считаются.

* Строка есть в момент подтормаживания — занят главный поток, последняя строка порт-лога перед ней называет код, который работал.
* Строки нет, а ожидание ~1 с остаётся — это не JS: сеть, сервер или анимация.
